# Ballast confidential trigger (Flare Compute Extension)

Bounty 2 of Flare Summer Signal. Keeps a borrower's liquidation trigger out of public storage.

## Why

Ballast v1 stores `Policy.triggerHealth` on-chain in the clear, so anyone can read every
protected position's exact trip wire. That is the single most useful thing a searcher could
ask for: push the oracle just above someone's trigger and you know no protective bid appears;
push it just below and you know one does.

Here the trigger lives inside a TEE. On-chain there is only
`keccak256(trigger, target, salt)`.

## Shape

```
borrower                    chain                     enclave
   │                          │                          │
   ├─ commit(hash) ──────────►│  ConfidentialTrigger      │
   │                          │                          │
   ├─ enroll(ciphertext) ────►│  InstructionSender ──────►│ decrypt via sign sidecar,
   │   encrypted to the       │  (event is public!)       │ check hash matches, hold
   │   machine's pubkey       │                          │ plaintext in memory only
   │                          │                          │
keeper                        │                          │
   ├─ evaluate(borrower,      │                          │
   │    market, blockNumber) ►│ ─────────────────────────►│ read position + price at
   │                          │                          │ that block, compare to the
   │                          │                          │ secret trigger
   │◄─ signed verdict ────────┼──────────────────────────┤ (polled from the proxy)
   │                          │                          │
   └─ execute(verdict, sig) ─►│  ConfidentialTrigger verifies the signer is a
                              │  PRODUCTION machine of this extension, then calls
                              │  BallastManagerV2.protectFor, which clamps to policy
```

Three constraints drove this design, all found by reading the chain and tee-node rather than
the docs:

1. **Instruction payloads are public.** They travel in a `TeeInstructionsSent` event. Hence
   the ciphertext, encrypted to `MachineManagerFacet.getPublicKey(teeId)`.
2. **Results never return on-chain by themselves.** The lifecycle ends at "caller polls the
   proxy", so a keeper relays the signed verdict.
3. **Evaluation must be pinned to a block.** Machines reading at different heights produce
   different result bytes, and the stack requires them to be byte-exact.

## Layout

| Path | Role |
|---|---|
| `config/config.go` | op constants, must match the Solidity `bytes32` constants |
| `types/types.go` | request/response types, ABI layouts, public state shape |
| `extension/ballast.go` | the ENROLL and EVALUATE handlers |
| `extension/chain.go` | pinned-block reads of Morpho position, market and oracle |
| `extension/sign.go` | decryption via the tee-node sign sidecar |
| `extension/framework.go` | **scaffold code, delete when dropping into the scaffold** |
| `contracts/BallastInstructionSender.sol` | the only address allowed to instruct this extension |

## Building

```bash
cd fce && go build ./... && go test ./...
```

To deploy for real, drop `config/`, `types/`, `extension/ballast.go`, `extension/chain.go`,
`extension/sign.go` and `contracts/BallastInstructionSender.sol` into a clone of
`flare-foundation/fce-extension-scaffold` on latest `main`, **delete
`extension/framework.go`** (the scaffold provides `buildResult` and `actionHandler`, and
duplicate definitions will not compile), then follow the scaffold's pre-build, post-build and
`register-tee` steps. `SIMULATED_TEE=true` reaches PRODUCTION in seconds and is accepted for
hackathon judging.

## Two invariants pinned by tests

Both are cross-language and both fail silently if they drift, which is why they are fixtures
rather than assertions about behaviour:

- **The signing digest.** `src/libraries/TeeResultHash.sol` reproduces the three-keccak chain a
  TEE machine signs, asserted in `test/TeeResultHash.t.sol` against a fixture generated by
  running Flare's own Go code, including recovering a real geth signature on-chain.
- **The commitment.** `extension/commitment_test.go` and
  `test/ConfidentialTrigger.t.sol::testCommitmentMatchesTheGoExtension` assert Go and Solidity
  hash a policy identically. If they diverge, every enrollment is rejected as "policy does not
  match published commitment" and nothing in that error says why.
